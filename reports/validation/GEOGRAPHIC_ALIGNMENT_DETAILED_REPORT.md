# Geographic Alignment — Detailed (CRS vs Snapping split)

Post-resize re-validation. The old single "0.0000 m" T1 number conflated two
different error sources; this report separates them.

- **E_crs** = `distance(original WGS84, SUMO x/y → WGS84 round-trip)` —
  measures the coordinate-reference-system round-trip fidelity.
- **E_snap** = `distance(facility original WGS84, SUMO snapped road/access point)` —
  measures how far the facility's *original* placement is from its road access
  point. Taken from the authoritative build-time `sumo_mapping.snapped_distance_m`.

## Interpretation

1. **CRS round-trip is exact** (0 m) for all six facilities — the SUMO
   `convertLonLat2XY ↔ convertXY2LonLat` pair is a lossless inverse over the
   testbed (no projected-CRS drift).
2. **H1 (42.854 m) and D1 (58.012 m)** are the two POI-derived facilities: their
   *original* location is a building centroid (hospital / depot) and their
   *snapped* point is the road access/landing site **V1 / V2**. This is expected
   and correct — the air/ground hand-off uses V1/V2, which sit **on** the road
   (snap = 0 m). D1's 58 m is the depot building → road distance, not a CRS error.
3. **V3 (27.48 m)** is the backup landing site: its original 400-m-NE anchor was
   snapped to the nearest road; the config retains the snapped coordinate and the
   build-time `snapped_distance_m`. It is < 50 m → OK.
4. **V1/V2/B1 snap = 0 m** by construction (defined on the road/edge).

## Verdict

**WARNING** (D1 snap = 58.0 m > 50 m). This is a *reporting* warning, not a
failure: D1's road access point V2 is exactly on the road (0 m), so no
re-placement is required. No facility exceeds 100 m, so no FAIL and no
re-placement analysis is triggered.
