## 1. 审计是什么

这是一份投稿前的**独立诚实度审计**，对实验二（E2）和实验三（E3）三站点共 **6,720 次**主运行
（E2 3,840 + E3 2,880）做了零信任复核。附带可复现脚本（`audit.py` / `diagnostics.py` /
`geometry_audit.py` / `probes.py`）与两次 SHA-256 清单（13,440 个文件，无内容变化）。

## 2. 核心裁决

| 实验 | 裁决 | 理由 |
|---|---|---|
| **E2** | 保留为"简化模型下的单故障响应基准"，**必须重新分析、收缩结论**；不必丢弃 3,840 次运行 | 共享输入/外生故障/配对种子设计有价值；但恢复率分母、候选收缩解释、统计校正、损害归因需修正 |
| **E3** | **作为正式论文主实验重新设计并重跑**；现有 2,880 次留作开发/诊断/旧版对照 | 全系统目标与调度触发机制不一致、背景任务生命周期不合理、L3 未形成声称的竞争、跨站点统计与故障归因错误 |

## 3. 必须撤回/改写的四条表述

1. **"Site B L2 中 LLM 因过度占用第二应急资源而显著更差"** → 撤回。
   L2 没有第二应急任务；+159 SWL 差主要伴随连接失败（143 次最终传输错误、17 个运行、6 个主应急未完成）。
   正确 Holm 值 ≈ **0.21135（不显著）**，不是 0.036。
2. **"Site A 三协调管理器 240/240 决策完全相同"** → 改写为"240/240 的 SWL 数值相同；操作/时间序列仅 235/240 相同，5 对完成时间不同"。
3. **"L2 的 +100 SWL 是第二次损失备用医疗机造成的"** → 撤回。真相是：+100 全部来自另外两个场景里**未再调度的背景任务**
   （客运/物流一直 `NEEDS_REPLAN` 无人处理），而非备用机被毁。
4. **"跨场地 B4b 零重试"** → 撤回。Site B 5 次、Site C 14 次结构化重试；另有 143（B）/1（C）次最终传输错误。
   `retry_count=0` 是因为传输异常直接返回、不进解析重试分支。

## 4. 技术问题清单

### P0（致命，影响结论有效性）
- **P0-1 全系统损失与背景任务生命周期不一致**：背景服务初始化即 `EN_ROUTE`、截止 1800s、到站不算完成，
  而 E3 在 900/1200s 结束，正常仍飞行的服务被按"取消"计费（**2,864/2,880 运行受影响**）。
- **P0-2 调度只触发应急任务**：`_periodic_due` 只查两个应急任务，背景 `NEEDS_REPLAN` 永不再触发；每事件只执行一个动作。
  `E3_L2_F2_F4` 中 B2 先救主应急、客运停到结束 → +100 来自背景任务。
- **P0-3 L3 未形成资源竞争**：Site A/B 无"两个应急同时待决"的决策时刻（Site C 仅 B4b 有 2 个）。
- **P0-4 跨站点把网络故障当策略劣势 + 显著性算错**：见第 3 节第 1 条。
- **P0-5 未完成任务被标成"不违约"**：`bool(comp_t and crit and comp_t > deadline)` 在 `comp_t=None` 时返回 False。
  E3 Site B B4b 逾期率应为 **24.58%**（59/240）而非 22.08%；B2 为 25.00%。

### P1（指标/统计缺陷）
- **P1-1 复合指标未实现或与定义不符**：`resource_competition_correct`、`priority_consistency_violations`
  在全部 2,880 个 metrics.json 缺失；`cascade_recovery` 回填模式（591 事件不符 + 67 非主任务事件误记成功）；
  `decision_oscillation_count` 实为"切换次数"。
- **E2 恢复率分母不一致**：跨站点表 0.625 等用全体 320 运行作分母；恢复时间应为 **191 对 / 3.9267s**（非 200/4.5s）。
- **E2 候选收缩混入派飞占用**：`candidate_set_reduction_delta` 非同一时刻因果差值。
- **统计实现错误（E2/E3 共用）**：`holm` 缺累积最大值 + NaN 处理错；McNemar `binomtest(...).pvalue * 2` 重复翻倍。

### 共同模型边界
- 地面 ETA 是自由流代理，且所有任务共用 D1→H1 ETA（未按起终点）；无真实接驳/交付。
- 恢复路径默认 V3 交接，无载荷守恒/取卸货时间。
- F2/F5/F6 是状态机简化；存在条带-路线几何缺陷（只查端点、漏检内部相交，正交穿越被判不相交）。
- 时钟冻结 + 接口日志双重限制：0s 重规划是仿真决策时间；传输错误不计入 `latency_s` 且被 `<1s` 规则误判为缓存命中。
- 跨站点只能支撑适配复现，不能单独归因于城市形态。

## 5. 代码级核实结果（本次独立核对）

| 指控 | 代码位置 | 核实 |
|---|---|---|
| 调度只查应急任务 | `orchestrator/experiment3_runner.py:225` `_periodic_due` | ✅ 只遍历 `self.emergencies` |
| SWL 对未完成任务收取消费 | `orchestrator/experiment3_runner.py:268` `_system_weighted_loss` | ✅ `else: loss = cancellation_cost` |
| 未完成→不违约 | `orchestrator/experiment1_runner.py:361` | ✅ `bool(comp_t and crit and comp_t > deadline)` |
| Holm 缺累积最大值 | `tools/analyze_experiment2.py:137`、`analyze_experiment3.py:132` | ✅ 只有 `ps[i]*(n-k)`，无 `max` |
| McNemar 重复 ×2 | 两处 `binomtest(...).pvalue * 2` | ✅ 默认双侧再翻倍 |

**结论：审计技术上可靠、措辞克制（明确区分"策略效应"与"接口/可靠性效应"，主动标注自身敏感性分析局限）。**
核心发现是实质性的，不是吹毛求疵。

## 6. 对项目结论的影响

1. 先前 `PROGRESS_REPORT.md` 中三条表述已被审计修正/推翻（L2 反噬归因、240/240 一致性、E3 跨站点"显著更差"），已同步修正。
2. 论文叙事需降级：E3 复合压力不可作主卖点；E2 的 B2–B4b 可比较结论方向仍成立但强度减弱
   （E2 A 总体完成时间差在 12 项检验族下 Holm p=0.0087，归因到后端可靠性而非策略）。
3. **仍可保留**：初始比较公平（1680 组配对首次输入一致、种子真实改变初始态）、候选表无优化解泄漏、
   故障外生、执行边界可靠（先规范化再校验、地面完成时间由环境算）、保留后台失败运行。
